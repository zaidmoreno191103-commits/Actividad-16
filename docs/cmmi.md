# Diagnóstico de madurez del proceso

## Nivel estimado

Nivel 2 – Gestionado

## Justificación

El equipo planificó el trabajo mediante un backlog y un Sprint, asignó responsables, utilizó control de versiones (Git/GitHub) y gestionó formalmente un cambio (CR-001) con análisis de impacto. Sin embargo, no se utilizaron métricas cuantitativas de productividad ni de calidad, ni procesos definidos a nivel organizacional, ni mejora continua sistemática (retrospectivas formales). Por ello, el equipo se encuentra en Nivel 2 (Gestionado).

## Evidencias

- Uso de GitHub con historial de commits.
- Uso de tablero Trello con columnas de flujo.
- Historias de usuario con criterios de aceptación.
- Gestión del cambio CR-001 documentada.
- Pruebas registradas en `docs/pruebas.md`.
- Documentación completa en `docs/`.
- Análisis de impacto del cambio.

## Áreas de oportunidad

1. Definir métricas cuantitativas (velocidad, bugs por sprint).
2. Automatizar pruebas (Jest, Cypress).
3. Establecer retrospectivas formales al final de cada sprint.
4. Documentar procesos estándar reutilizables en otros proyectos.
