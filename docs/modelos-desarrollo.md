# Selección de modelos de desarrollo

| Escenario | Modelo seleccionado | Justificación |
|---|---|---|
| A – Sistema bancario | Cascada (V-Model) | Los requisitos están regulados, son detallados y estables. Se requiere documentación exhaustiva, trazabilidad y control riguroso. El costo del cambio es alto, por lo que conviene un enfoque secuencial. |
| B – App móvil para estudiantes | Scrum (Ágil) | El cliente no conoce todas las funcionalidades. Se necesitan entregas frecuentes y retroalimentación continua para descubrir requisitos. |
| C – Planta nuclear | Espiral | El riesgo es extremadamente alto. El modelo Espiral permite identificar, analizar y mitigar riesgos en cada iteración antes de avanzar. |
| D – Startup (MVP) | Scrum / Kanban | Se requiere lanzar rápido un MVP, los requisitos cambian constantemente y el usuario final retroalimenta el producto. |

## Conclusión

Los factores considerados para seleccionar cada modelo fueron:

1. **Estabilidad de los requisitos**: A mayor estabilidad → Cascada. A mayor cambio → Ágil.
2. **Nivel de riesgo**: A mayor riesgo → Espiral o V-Model.
3. **Participación del cliente**: Si el cliente puede retroalimentar con frecuencia → Scrum.
4. **Frecuencia de entregas**: MVP o startups → iteraciones cortas.
5. **Regulación y documentación**: Sectores regulados → Cascada con documentación formal.
6. **Costo del cambio**: Si el cambio es costoso → planificación anticipada.
