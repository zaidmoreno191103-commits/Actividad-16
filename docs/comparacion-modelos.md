# Comparación de modelos de desarrollo

| Característica | Cascada | Scrum/Kanban |
|---|---|---|
| Requisitos | Fijos al inicio, documentados exhaustivamente | Emergentes, refinados por iteración |
| Cambios | Costosos y formales | Bienvenidos y gestionados por backlog |
| Entregas | Única entrega al final | Entregas incrementales cada Sprint |
| Participación del cliente | Baja, solo al inicio y al final | Alta, en cada revisión de Sprint |
| Flexibilidad | Muy baja | Muy alta |
| Riesgo | Alto si cambian requisitos | Mitigado por iteraciones cortas |
| Documentación | Exhaustiva y formal | Suficiente y viva |

## Pregunta principal

**¿Cuál de los dos enfoques consideras más apropiado para el proyecto Task Manager y por qué?**

Scrum/Kanban es más apropiado porque:

1. Durante el laboratorio apareció un requisito nuevo (CR-001) que no estaba previsto.
2. El cliente pudo retroalimentar el producto de forma continua.
3. Las entregas fueron incrementales (Sprint 1: US01–US03; luego CR-001).
4. Con Cascada, el cambio CR-001 habría implicado rehacer fases completas de análisis y diseño, con mayor costo y tiempo.

La experiencia del laboratorio confirma que en proyectos con requisitos cambiantes, un enfoque ágil responde mejor.
